# Week 5 — Activity Diagram

## 1. Process Modelled
Volunteer applies for an event role (use case: Register for Events) in the Community Volunteer and Event Coordination System.

## 2. Purpose
The diagram shows the steps of applying for a role. It also shows one decision and one missing rule.

## 3. Activities
1. Select Event Role.
2. Check role requirements.
3. Submit application.
4. Application recorded.

## 4. Decision and Guards
Decision: Does the role need particular skills or experience?
[yes]: leads to the box "How are skills or experience checked". This box is an unknown, not a step. The scenario does not say how skills or experience are checked.
[no]: the volunteer submits the application

## 5. Unknowns
How are skills or experience checked
What happens when a volunteer does not have them

## 6. Stakeholder Question
To the Event Organiser: "For roles that need particular skills or experience, how do you check them today, and what happens if a volunteer does not have them?"

## 7. Modelling Decision
I did not add rejection, approval or a waiting list, because the scenario does not support them. The diagram ends after the application is recorded. Approval is a separate step.

## 8. Reflection
The diagram helped me see the order of steps in applying for a role. It showed a missing rule: how skills or experience are checked. I need to ask the Event Organiser before I define this behaviour.
